## Build (from Windows)

Builds run on the devcloud Mac `vmui-mac` (Xcode 26.6) and ship the **committed** tree only:

```powershell
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode test      # swift test MixaiCore
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode build     # unsigned device compile
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode devipa    # development IPA for registered devices
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode upload    # TestFlight (needs the App Store Connect app record)
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode musicbuild    # MixAI Music, unsigned device compile
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode musicupload   # MixAI Music to TestFlight (group "MixAI Music internal")
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode decksbuild    # MixAI Decks iOS/iPadOS: Rust xcframework + unsigned compile
pwsh -NoProfile -File scripts/ios-build.ps1 -Mode decksmacbuild # MixAI Decks macOS: universal Rust lib + unsigned compile
```

Before signed modes: the Mac clock must be synced (`sudo sntp -sS time.apple.com`) and the VM kept awake for the
whole build (hold an SSH session). Install a dev IPA on the iPhone through codai's iPhone bridge:
`pwsh -NoProfile -File E:\gh\codai\scripts\ops\ios-dev.ps1 -App ro.mixai.app -Ipa <ipa> -Match MixAI`.

Remote packages (exact pins, first resolve downloads ~1 GB into `~/.cache/mixai-ios-spm` on the Mac): VLCKit
`4.0.0-a25` (LGPL-2.1-or-later, dynamically linked) and sentry-cocoa `9.33.0` (DSN from the `SENTRY_DSN` build
setting; empty = Sentry off, `sendDefaultPii = false`).

## Playback

Video = server HLS remux of the original (`/video/stream/{id}?q=original&caps=…&start=&audio=`), so HLS time 0 is
the `?start=` offset; the player keeps absolute positions and restarts the stream when seeking before the offset.
Audio track = new session with `audio=<ordinal>`; subtitles = `/video/subs/{id}/{ordinal}` WebVTT rendered as an
overlay (absolute times). `PlaybackEngine` is the seam for the later VLCKit fallback.

When AVFoundation refuses a file (format/decoder errors, `shouldFallBackToVLC`), the player switches to `VLCEngine`
on the original file (`/video/direct`). Downloads are server MP4 remuxes (`/video/download?container=mp4`) fetched by a
background URLSession; offline files play without the server and their progress is queued until it is reachable.
