## 3. (b) Top 3 recommendations

1. **Flexible beatgrid with tempo markers, a fixed‑grid toggle and encoder‑drift correction (#1 + #3).**
   - Every major competitor now has some form of flexible grid, so without one Decks looks unfinished.
   - Serato's version has visible faults, and nobody fixes drift.
   - It improves every later feature: sync, automix, stems and cue import.
   - It fits the Rust core and the ONNX model (Beat This! weights are MIT).
2. **OneLibrary and cross‑app import with a free hardware unlock (#2 + #10).**
   - Switching cost is the main thing holding DJs on rekordbox, which has a 34 % share and an annoyed user base.
   - Decks already reads PDB, so this mostly extends existing code.
   - Message: "Bring your rekordbox library, keep your cues, no subscription."
3. **A local "co‑pilot": next‑track suggestions, the natural‑language set builder and stem‑aware automix (#6–#8).**
   - rekordbox charges for this in its cloud tiers; VirtualDJ ships it online.
   - Offline, private and free on top of the existing stems and key/BPM analysis is a clear angle.
   - It targets the use the census says DJs actually want AI for.

Alternative third pick: library safety (#11). It is cheap and answers the most emotional Serato complaints.

## 4. Licensing traps

- **Mixxx is GPLv2‑or‑later.** Because of "or later" its code can be used under GPLv3, and GPLv3 code may be combined with AGPLv3 code (GPLv3 §13 / AGPLv3 §13).
  - However, extra permissions such as exceptions for proprietary plugins, app stores or closed skins cannot be applied to GPL‑derived code. GPL §7 lets downstream users remove them, and GPL forbids adding restrictions.
  - Copying Mixxx code would therefore cancel the "with exceptions" part and any dual or commercial licensing, and would cause problems with App Store distribution.
  - **Reimplement from file‑format specs and papers; never copy Mixxx code.** Mixxx skins and mappings carry their own licences, so check each one.
- **Other licences to avoid or handle carefully:**
  - libkeyfinder is GPL‑3, so the same trap applies.
  - Ableton Link and rusty_link are GPLv2+ unless you buy Ableton's commercial licence.
  - Chromaprint is LGPL‑2.1 (FFT parts may be GPL depending on the build). Dynamic linking is acceptable on desktop but awkward on iOS, so a custom fingerprint may be safer.
  - Essentia models are CC BY‑NC‑SA, which rules them out for commercial use.
  - AudioShake (behind djay's stems) is commercial.
  - The VST3 SDK is now MIT and safe to use.
- **Streaming requires partner agreements**: Spotify, Apple Music, Beatport (which absorbed Beatsource in 2026), TIDAL and SoundCloud all need business deals. The Spotify and Apple Music DJ integrations are personal, non‑commercial use only, with no offline playback, no stems and no recording. Engine also denies stems on Apple Music.
- **OneLibrary**: AlphaTheta publishes no open specification. VirtualDJ reverse‑engineered the format before joining officially. The safe route is to ask AlphaTheta for partner access; a clean‑room implementation for interoperability is a fallback with legal risk.
- **AI features**: generated voice drops and AI lyrics need visible AI labelling under EU AI Act art. 50. Lyric display can also raise licensing questions for public performance and karaoke.

The solver works in four steps:
1. Split the window into weighted columns and rows.
2. Give each area the union rectangle of its cells.
3. Pick the richest tier that fits that rectangle.
4. If nothing fits, an essential panel drops to `icon` and a non-essential one is docked. The dock host is the largest non-essential placed panel, otherwise the largest panel.

`validateLayout` enforces:
- slug ids;
- 1–8 weights in (0, 20];
- gap 0..32;
- no overlaps;
- deckA, deckB and mixer are required.

`minimumSize` uses only essential panels at the icon tier.

**`apps/mixai/src-tauri/src/pack.rs`** (~1453 lines):
- **Lines 1–905: pure, no I/O.** Limits at L23–37 (25 MB archive, 200 entries, 10 MB per entry, 60 MB total, ratio 100, 64 KB per layout, 512 KB preview, 2 MB inline assets, 8 fonts, reserved prefix `ro.mixai.`). Also:
  - types `PackManifest`, `PackTokens`, `PackInfo`, `PackTrust` (L113–216);
  - `read_archive`, a zip with bomb, traversal and extension guards (L398);
  - `canonical_digest` (L495);
  - `verify_signature`: Ed25519 `verify_strict`, with official/verified key tables or an embedded pubkey giving community trust (L517–559);
  - `validate_manifest` (L583), `validate_tokens` (L668), `read_layout` (L790);
  - `inspect_with(bytes, keys) -> PackInfo` (L809) and `inspect` (L871);
  - `sign_pack` (L879).
- **Lines 905–1100: Tauri-bound.** Storage uses `AppHandle` (`packs_dir`, index.json, atomic writes), plus the commands `pack_inspect/install/list/remove/pick_file`. Registered in `src-tauri/src/lib.rs:28,1092-1096`.
- **Lines 1101+: tests** (signature, tamper, traversal, svg, bomb, colours, reserved ids).
- Dependencies are in the workspace `apps/mixai/src-tauri/Cargo.toml:49-52`: `zip 9.5` (deflate zlib-rs), `ed25519-dalek 3`, `sha2`, `base64`. The workspace members are `crates/*` (L15), so a new crate needs no workspace edit.

## 2. Android and Desktop Decks (KMP, Compose Multiplatform)

- **Layout today is fixed Compose code.** There is no grid or panel concept. `DecksScreen.kt:90-160` uses `BoxWithConstraints` with two breakpoints, `wide = maxWidth >= 1000.dp` (L101) and `tall >= 1100.dp`. It branches on the `DeckLayout` enum (`Classic`, `Performance`, `Library`, `Skins.kt:18-30`) into hard-coded `Row`/`Column` blocks.
  - Short and narrow windows **scroll** (L137-156, `verticalScroll`). That breaks the zero-scroll contract.
  - Panels: `DeckPanel(ctl, i, modifier, compact: Boolean)` (`DeckPanel.kt:40`), `MixerPanel` (`MixerPanel.kt:31`, which also holds the crossfader), `LibraryPanel` (`LibraryPanel.kt:44`), plus overlay panels Connect, Ai and Set.
  - There are only two tiers (compact true/false) and no icon tier. There are no standalone composables for clock, crossfader, automix, sampler or plugins.
- **Colours** come from `Skins.kt`:
  - `DecksSkin` (accent name, surface, density, radius, motion, layout, contrast; encoded as `k=v;…` with no JSON).
  - `DecksPalette` derives every role from `TokenRoles` OKLCH plus the accent hue.
  - The `Oklab` object has `toSrgb` and WCAG `contrast` (`Skins.kt:96-160`).
  - `DecksTheme.kt`: a `DecksColors` snapshot-state singleton. Deck colours are brand-fixed from `Tokens.brandDeckA..D` (L54).
  - `TokenRoles.kt` and `Tokens.kt` are synced from `apps/mobile-android-common` by the `syncTokens` task (`ui/build.gradle.kts:20-27`).
  - There is **no hook for arbitrary colour overrides**. A pack's `colors` map (hex/oklch per key) has no place to go today. `DecksPalette` would need an override map.
- **Zip / Ed25519:** no dependency for either. `ui/build.gradle.kts` pulls only cmp runtime/foundation/ui, coroutines, kotlinx-serialization-json (androidMain/desktopMain), JNA and activity-compose. `java.util.zip` exists on the JVM, but there is no Ed25519 with `minSdk = 29` without adding BouncyCastle or Tink.
- **decks-ffi is already wired on both targets:**
  - `core/build.gradle.kts` runs cargo-ndk on `decks-ffi` into jniLibs and generates UniFFI Kotlin bindings with `uniffiBindgen` (package `ro.mixai.decks.ffi`).
  - `ui` adds the bindings to desktopMain (`bindingsSrcDir`, L29-30) and `api(project(":decks-core"))` to androidMain.
  - The adapters live in `ui/src/jvmShared/kotlin/.../engine/Ffi*.kt`, behind commonMain ports (`TransitionPort.kt:49`, `RemotePort`, `SetRecordPort`) with demo fallbacks.
  - `apps/decks-desktop` reuses `:decks-ui` (only `Main.kt`).
- **Exposing pack verification through decks-ffi is feasible and cheap.** The crate (`crates/decks-ffi/Cargo.toml`) already uses `serde_json` and the JSON-string pattern (`action_json`, `automation_json` in `mapping.rs` and `transition.rs`). Errors go through one `DecksError` enum (`lib.rs:46-80`), where a `Pack { reason }` variant would fit.

## 3. iOS Decks (SwiftUI)

- **Layout:** `RootView.swift` branches only on `horizontalSizeClass`:
  - `regular` (L67-81): waveforms, then a horizontal `ScrollView` of Deck | Mixer | Deck, then the library.
  - `compact` (L83-110): a segmented tab picker over scroll views.
  - There is no grid, tier or skin concept.
- **Colours:** `Support/DecksTheme.swift` is a static enum fixed to `Tokens.Dark.*` from `MixaiCore`. There are **no skins at all**: no light mode, no accent, no runtime palette. iOS needs a `DecksPalette` equivalent before any pack skin can apply.
- **Zip / Ed25519:** Foundation has no zip API. CryptoKit has `Curve25519.Signing` (Ed25519), but its verification is not guaranteed to be `verify_strict`-equivalent. Re-implementing the zip guards in Swift would be the largest duplication.
- **DecksFFI:** `apps/ios/DecksFFI/Package.swift` wraps a generated `DecksFFI.xcframework` (from `apps/ios/scripts/build-decks-xcframework.sh`, gitignored). Any new `#[uniffi::export]` in decks-ffi appears in Swift automatically after a rebuild.

## 4. Recommended architecture

**Verification, parsing and the solver all go in Rust (one implementation for Kotlin and Swift). The TypeScript solver stays on the Tauri desktop, cross-checked by shared golden fixtures.**

Why:
- Kotlin has no Ed25519 at minSdk 29, and Swift has no zip support. Porting the ~900 lines of guards twice is the main duplication risk, and it is security code.
- The solver is ~150 lines. Putting it in Rust removes two ports (Kotlin and Swift) and leaves one TS↔Rust parity check, instead of three implementations drifting. It runs once per resize, so the FFI call cost is negligible.
- The Tauri renderer keeps its synchronous TS solver. That avoids an IPC round-trip on every resize and keeps the existing `solver.test.ts`.

### Notes and risks
- **The panel sets don't match.** Native apps lack clock, automix, sampler and plugins. Either map these to the dock or have the native `validate` accept unknown panels as "unavailable → docked". This must be a deliberate choice, because `validateLayout` rejects unknown panel ids.
- **Units.** Treat `PANEL_SPECS` px as dp/pt. Then re-check that each native panel actually renders within `min[tier]` with the zero-scroll probe or screenshot tests. That contract is enforced on desktop only (`presets.ts` header).
- **iOS needs a rebuild step.** It only sees new FFI functions after `build-decks-xcframework.sh`. Android and Desktop regenerate bindings automatically through `:decks-core:uniffiBindgen`.
- **Rough total:** Rust ~700 new lines (mostly moved), Kotlin ~800–1000, Swift ~600–700, plus docs and fixtures.
